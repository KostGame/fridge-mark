# GS1 Parser

PR002 добавляет локальный парсер GS1 Application Identifiers без запросов к внешним API.

## Поддержанные AI

- `01` — GTIN, фиксированная длина 14 цифр.
- `10` — batch/lot, переменная длина до 20 символов.
- `11` — дата производства, `YYMMDD`.
- `15` — best before date, `YYMMDD`.
- `17` — expiration date, `YYMMDD`.
- `21` — serial, переменная длина до 20 символов.
- `7003` — expiration date and time, `YYMMDDhhmm`.

## Форматы входа

Парсер принимает:

- строку с ASCII Group Separator 29;
- строку с текстовым `\u001D`;
- строку с symbology identifier `]d2`;
- человекочитаемый формат с круглыми скобками, например `(01)04601234567890(17)260501(21)ABC123`;
- строку без скобок, например `01046012345678901726050121ABC123`.

Для переменных AI `10` и `21` конец значения определяется по Group Separator, по максимуму длины или по следующему известному AI, если его можно найти.

## Даты

`YYMMDD` преобразуется в `YYYY-MM-DD`. Если `YY < 50`, используется `20YY`, иначе `19YY`. Невалидные месяц, день, часы или минуты добавляются в `errors`.

`7003` сохраняется как локальная дата-время без timezone в формате `YYYY-MM-DDTHH:mm`.

## Ограничения

- Парсер не гарантирует полную поддержку всех GS1 AI.
- В строках без Group Separator переменные поля могут быть неоднозначны.
- Название продукта по GTIN не определяется.
- Проверка подлинности кода маркировки не выполняется.

## Почему не используется API Честного знака

PR002 сохраняет MVP полностью локальным: без сервера, API-ключей и сетевых запросов. Это позволяет запускать приложение как PWA на Android и публиковать статическую сборку на GitHub Pages.

## Почему rawCode сохраняется полностью

Даже если локальный парсер распознал не все поля, полный исходный raw-код нужен для будущего повторного парсинга, диагностики форматов сканеров и возможной интеграции с внешними адаптерами в более поздних PR.
